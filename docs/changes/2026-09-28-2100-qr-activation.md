# QR code and share for patient activation codes

Opened: 2026-09-28 21:00 PHT

## What
- When the desk issues an activation code, the patient page now shows:
  - a **QR code** for `/register?code=…`;
  - **Share…**, the phone's share sheet (Viber, Messenger, SMS from the clinic's own phone), shown where the device has one;
  - **Copy message** and **Copy code**.
- The QR link uses the address the desk is browsing (`lib/activation-link.ts`), not `APP_URL`, so a patient's phone can open it. In dev, `APP_URL` is `localhost`. Email links still use `APP_URL`.
- `/register?code=…` offers **Open in the medfave app** (`medfave://activate?code=…`). The web form below still works with the code filled in.
- New dependency: `qrcode` (plus `@types/qrcode`), which renders the QR as inline SVG on the server.

## Why
A free way to get codes to patients instead of SMS (see `PRODUCT.md`): scan at the desk, or send by Viber or Messenger.

## Tested
- `tsc` and eslint pass.
- In a browser as the desk (test data only):
  - issued a code for a patient without a login; the code, QR code and Share/Copy buttons render with no console errors;
  - the QR matches, path for path, a QR generated for `http://localhost:3000/register?code=<code>`;
  - that link opens the register page with the code filled in and the app button pointing at `medfave://activate?code=<code>`.
- **Not tested:** scanning with a real phone camera, and the share sheet on a phone. The app side of the deep link comes in the mobile PR.

## Heads-up
- The "Open in the medfave app" button only opens a real (EAS-built) app. Expo Go uses its own `exp://` links, so in development patients use the web form or type the code into the app.
- Copy needs a secure context (HTTPS or `localhost`). On a LAN `http://` address the browser blocks the clipboard, and the code on screen is the fallback.
