# Doctor API; booking rules moved to lib/booking.ts

Opened: 2026-09-28 20:06 PHT

## What
- **`lib/booking.ts`** now holds the booking rules that lived inside `app/actions/appointments.ts`: `resolveBooking`, `lockDoctorSchedule`, `findClash`, `queueStamps` and `confirmByEmail`, plus two new entry points, `bookAppointment(actor, input)` and `changeAppointmentStatus(actor, id, status)`. The server actions are now thin wrappers with their same redirects.
- **Accept and decline moved** into `lib/requests.ts` (`acceptAppointmentRequest`, `declineAppointmentRequest`).
  - **Behaviour fix:** accepting used to run a hand-written overlap check over a ±12-hour window. It now uses the shared `findClash` for the clinic day, like every other booking.
  - Its duplicate confirmation-email function is gone; it uses `confirmByEmail`.
- **Doctor endpoints** under `/api/v1/doctor`:
  - `day`, `week` and `clinic`;
  - `patients` (search) and `patients/:id`;
  - `appointments` (book or walk-in) and `appointments/:id/status`;
  - `requests`, `requests/:id/accept` and `requests/:id/decline`.
  - The gate (`apiDoctor`) matches `requireDoctor`.
- **Clinic info:** `/patient/clinic` and `/doctor/clinic` share `clinicBookingInfo`. Service minutes now reflect the clinic's own durations.
- `docs/api.md` documents the doctor section.

## Why
The third step of the build order in `PRODUCT.md`: the doctor side of the mobile app needs a real API.

## Tested
- `tsc` and eslint pass.
- 25 API checks against the dev database (test data only), all passing:
  - patient and secretary tokens are refused on doctor endpoints (403);
  - day, week, clinic, patient search and detail work, and an unknown patient gives 404;
  - a walk-in for a slot that already ended today is refused;
  - booking works, an overlapping booking gives 409, and invalid fields give 422;
  - CONFIRMED to COMPLETED gives 409, a bogus status gives 422, and CONFIRMED to CHECKED_IN to CANCELLED works;
  - the patient requests; the doctor sees them, gets 422 accepting "any time" without a time, accepts with a time, gets 404 accepting twice, and declines with a note, which the patient sees.
- Everything booked by the test was cancelled again.
- **Web, through a real browser:** a doctor restored a cancelled appointment (the locked path) and cancelled it again with the page's own buttons.
- **Not browser-tested:** the web booking form and the desk's accept and decline buttons. They now call the same `lib` functions the API tests exercised.

## Not done / next
- The doctor side of medfave-mobile on this API.
- There's no endpoint for writing clinical notes. That stays on the web by design.

## Heads-up
Any new code path that books or moves an appointment into a slot must use `lib/booking.ts`. Don't write another overlap check.
