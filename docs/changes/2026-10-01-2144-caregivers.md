# Caregivers: a login that looks after somebody else's chart

Opened: 2026-10-01 21:44 PHT

## What
- New `CareLink` table: a login looks after a chart (a child, a parent in their care) without becoming that patient. The login keeps its own chart, and can still add one, at the same clinic.
- The desk decides who is a caregiver. On a chart, the **Looked after by** card issues a caregiver code (with the caregiver's name), lists caregivers, and has Remove (a link is revoked, never deleted). A caregiver code is never emailed to the patient's address.
- Redeeming a caregiver code (Add a clinic, or a new account) creates a `CareLink`. The "Is this you?" step says "This code lets you look after …", and the button reads **Yes, I look after them**.
- Portal: **Me / Maria** pills switch whose records show at the current clinic. The clinic switcher shows each clinic once.
- API: `?patient=` or `X-Patient-Id` picks the person. Charts carry `self` and `name`. `docs/api.md` now covers this and `POST /activation/preview` from #94.

## Why
The user asked for this: a mother redeeming her daughter's code made her login *be* the daughter, with no room left for her own chart. The desk decides whether a code is for a caregiver, since the desk identifies people.

## Not done / next
- Mobile: a person switcher and `?patient=`. The app still shows the login's own chart.
- Caregiver access doesn't end on its own (for example when a child turns 18). It lasts until the desk removes it.
- A request for a **new patient** made by a caregiver still links the new chart to the requester as their own.
