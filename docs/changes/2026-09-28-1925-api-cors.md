# CORS on the mobile API; write calls tested

Opened: 2026-09-28 19:25 PHT

## What
- `next.config.ts` sends CORS headers (`*`) on `/api/v1/*` only, so the app's web build can call the API. Web pages are untouched.
- `docs/api.md` gains a "Cross-origin" section.

## Why
Checking the mobile app in a browser (Expo web on its own port) needs the API to allow other origins. Bearer-token auth makes `*` safe: no cookies are involved.

## Tested
- Preflight (`OPTIONS`) returns 204 with the headers; API responses carry `Access-Control-Allow-Origin`; `/login` has no CORS headers.
- **The PR #18 write calls, now tested** against the dev database (test data only) as the seeded patient:
  - invalid input gives 422 with field errors;
  - a Sunday gives 422 ("The clinic does not open on that day");
  - a valid request is created as PENDING and shows in the list;
  - withdraw gives WITHDRAWN, and a second withdraw gives 404.
- The test request was withdrawn, so it doesn't sit in the desk's queue.

## Not done / next
`POST /auth/activate` is still untested: it needs a fresh activation code from the desk.
