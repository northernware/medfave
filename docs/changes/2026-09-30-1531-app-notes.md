# Visit notes from the app

Opened: 2026-09-30 15:31 PHT

## What
- **`lib/consultation.ts`:** the note-writing code (drafts, signing,
  amendments with a reason, version trail, prescriptions, teleconsultation
  limits) moved out of `app/actions/records.ts`, unchanged, so the web form
  and the app's API share one implementation.
- **API:** `POST /api/v1/doctor/records` (draft / finish, JSON → the form's
  encoding), `GET /api/v1/doctor/records/:id` (read or continue; logged),
  `GET /api/v1/doctor/records?appointmentId=` (the draft already started for
  an appointment). A new note for an appointment that already has one of this
  doctor's continues it. `docs/api.md` updated.

## Why
Mobile-first, step 2: doctors write up a consultation on their phone.

## Tested
- `tsc` and `eslint` pass. API: draft → autosave to the same row → sign with
  a prescription → amend without a reason refused (422) → with a reason saved,
  2 versions; read back; Dr. Ramos gets 404 on Dr. Lim's note (private mode).
- With medfave-mobile's `app-notes`, 11 checks in the app (see that note).
- The web's note form was not re-run in a browser; its code path is the moved
  function, unchanged, and typechecks.

## Heads-up
- Note writing lives in `lib/consultation.ts` now; `app/actions/records.ts`
  keeps the web's actions only.
